### Telegram: notify only home visits and trading

**Cause:** jay (2026-10-09) wanted Telegram cut down to two kinds of message in each project: in Verex, home page and trading; in rabbit, home page and Jay Chat. A visitor returning within an hour should not ping again.

**Reasoning:** The API pinged on resolve, UMA propose, dispute, jury finalize, faucet, and MM config. Those are our own demo clicks far more often than a visitor's, and they buried the two signals that matter. Stripe funding (`💳`) is kept as part of trading: it is real money going into a trading account, and the only alert for a mint left PENDING. jay can still ask to drop it. In-memory debounce is per Cloud Run instance, which is acceptable for a "someone looked" ping. The same note already sits in the file.

**Change:** `packages/api/src/index.ts` has 9 `notifyTelegram` calls removed. Kept: `💱 trade` and `💳 funded`. The now-unused `verdict` local in `/uma-resolve` is removed. The policy is written in the header of `packages/api/src/telegram-notify.ts`. In `packages/web/src/lib/visitor-notify.ts` the home-visit `DEBOUNCE_MS` goes from 5 min to 1 h.

**Result:** `tsc --noEmit` is clean in api and web. Not yet deployed to prod: the re-deploy needs `SKIP_SEED=1 ./scripts/deploy-prod.sh`, and the runbook asks for it to be run with jay.
